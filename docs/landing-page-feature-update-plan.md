# 企业智脑官网改版实施计划

需求与验收标准以[主仓规格 #388](https://github.com/YinXiaoyu-1998/SME_DATA_CENTER/issues/388) 为准。本计划供官网实现者安排素材、代码改动和验证顺序。实施计划先行提交，官网改动随后通过独立的功能 PR 交付。

面向连锁餐饮负责人、区域经理和店长。访客读完首屏和第一个案例，应能解释三件事：企业智脑把哪些资料放到了一起，自己的 Agent 如何按权限组合使用，以及结果能帮助门店做什么决定。

## 首页阅读顺序

1. **首屏**。建议标题「把收货、配方和销售放在一起看」。副文案「企业智脑把散在不同报表里的经营资料归集到一处。店长和总部可以用自己的 Agent 查资料、做估算、准备经营会。」主按钮「看一次羊肉补货估算」，次入口「读一份完整周报」。
2. **跨数据案例**。紧接首屏，以一家门店、一个营业周、同一种原料讲完从提问到决定的过程。案例中的收货台账、成本卡、菜品销售分别链接到下方对应板块。
3. **经营周报与功能目录**。先展示可打开的新版周报，再按经营分析、门店执行、总部管理、接入与自动化分组。12 个功能各有独立标题和锚点。跨数据案例单独展示，周报入口复用同一个周报板块。
4. **服务与联系**。沿用现有的自行接入、开发者协助、任务指南、FAQ 和联系入口。保留深墨色、纸白、砖红与现有字体。桌面首选大图配短文，手机先读结论再看局部大图。

## 首页主案例 · 这周要补羊肉吗？

**店长提问**　「上周日收档盘了 12 斤羊肉，门店补货线是 20 斤。帮我算算这周还剩多少，要不要订货？」

| 依据       | 示例门店本周记录                        | 如何使用                                                                                       |
| ---------- | --------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 收货台账   | 本周两笔同规格净羊肉，30 公斤和 20 公斤 | 从已授权的每日台账 PDF 核对品名、规格、数量和单位，合计 50 公斤，即 100 斤。                   |
| 菜品销售   | 羊肉串 400 份、炖羊肉 80 份             | 采用同店同周期的实际销量。示例中只有这两道菜使用该原料，每份规格固定。                         |
| 菜品成本卡 | 羊肉串每份 75 克，炖羊肉每份 250 克     | 取已核实适用于该店和该周的生羊肉投料量。两道菜分别对应 30 公斤、20 公斤，合计理论耗用 100 斤。 |
| 门店提供   | 期初盘点 12 斤，补货线 20 斤            | 本例假设期间无其他调拨、退货、报损或非销售领用，收货和配方采用同一原料口径。                   |

**Agent 的答复示例**　「按本周销量和配方估算，店里还剩约 **12 斤**羊肉，比你设的补货线低 **8 斤**。建议今天收档先盘点实物，再联系供应商安排补货。」

**画面**。用真实台账 PDF 局部作第一张图。第二张用 Codex 或 WorkBuddy 风格的静态对话，在回答下列出两道菜的「销量 × 每份用量」。最后一行直接给出「期初 12 ＋ 收货 100 − 理论耗用 100 ＝ 预计余量 12 斤」。图和正文共用一套数字，图注标明模拟门店。8 斤是与补货线的差额，订货数量还取决于到货时间和后续需求。

**实现口径**。收货端走员工可读取的成品台账 PDF，成本卡和销量按现有授权取得，由员工的 Agent 计算。示例中的期初盘点与补货线由店长在对话提供。若期初盘点未知，只给出期间净变化；缺台账、单位无法换算、配方版本或门店例外有歧义时，标明待核对项。套餐按实际售出子菜处理，排除与普通销量重复的部分。首页展示本次询问产生的提醒；现有自动任务板块仍介绍入库、评价、周报三类工作流。

## 12 个功能板块与取景清单

每块用一个功能名、一至两句业务描述、1–3 幅画面。真实网页均从当前业务前端渲染，可用模拟接口响应。员工使用自己 Agent 的对话统一标「Agent 使用示例」。报告、PDF 和审阅表直接展示对应的业务成品。

| 分组         | 功能与用途                                                                                   | 要制作的画面                                                                               |
| ------------ | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 经营分析     | **多店经营周报**。在经营会前找出优先复盘的门店，并把变化追到餐段、档口和菜品。               | 从新版脱敏 HTML 截经营顾问反馈、门店四象限、档口归因，共 3 幅。点击可读全篇。              |
| 经营分析     | **经营数据归集与查询**。按门店和营业日归集营业、菜品、店内订单和平台外卖订单，支持临时追问。 | 1 幅 Agent 对话，从某店午市收入下降追问订单量和客单价，带同口径对比期。                    |
| 经营分析     | **菜品、套餐与档口归属**。维护菜品规格和套餐组成，核对实际售出的子菜及其部门归属。           | 2 幅 Agent 示例，分别展示可选子菜和实际子菜销量及归属。                                    |
| 经营分析     | **菜品成本卡与配方**。按菜品规格取标准用量和门店例外配方，供后厨核对备料。                   | 1 幅 Agent 示例，展示羊肉串的具体规格、原料、单位和适用条件，与首屏案例对应。              |
| 门店执行     | **门店巡检与反馈**。总部定义标准，门店按现场证据填报，也可让 Agent 整理记录、提出复查建议。  | 模板编辑页、Agent 根据现场描述填写并给出建议、同一道题的真实填写页，共 3 幅。              |
| 门店执行     | **收货台账与检疫凭证**。按门店和进货日期查找台账，核对收货记录和关联凭证。                   | 真实台账下载中心、从模拟数据生成的成品 PDF，共 2 幅。                                      |
| 门店执行     | **顾客评价与回复**。汇集美团和点评评价，准备回复，按授权审阅、发布并核对状态。               | 实际审阅表的模拟记录、负责人确认发布范围的 Agent 对话，共 2 幅。                           |
| 总部管理     | **企业资料检索与溯源**。按权限查询制度、SOP 和企业档案，查制度时可定位依据。                 | 1 幅 Agent 查闭店交接要求并引出示例 SOP 原文。在短文中说明会员、供应商档案也可按授权查询。 |
| 总部管理     | **门店、部门与员工档案**。登记员工所属门店及部门，维护总部直属员工和门店目录。               | 真实员工档案列表和归属编辑界面，共 2 幅。                                                  |
| 总部管理     | **账号权限与资料密级**。按资料类别、门店范围和密级分配读取权限。                             | 同一示例账号的真实业务授权页、对应资料类别设置，共 2 幅。                                  |
| 接入与自动化 | **企业自动任务**。分别配置每日入库、评价处理、经营周报，核对执行电脑与运行状态。             | 真实任务配置与最近执行状态，共 2 幅；接入现有任务指南。                                    |
| 接入与自动化 | **用自己的 Agent 接入**。员工从熟悉的 Agent 发起安装，再通过第一方页面确认登录。             | 现有安装演示和使用模拟身份的真实登录确认画面，共 2 幅。                                    |

## 最终验收

- **读得懂**。访客从首屏进入羊肉案例，能找到收货量、两项理论耗用、期初盘点及补货线，并说明提醒依据。页面将结果称为「预计余量」，用「建议复盘、安排补货」表达动作。
- **找得到**。12 个独立板块均可通过分组导航到达，每块 1–3 幅画面。既有业务 UI 使用真实前端截图，对话示例可辨认。巡检三幅图展示同一题，羊肉案例的原料和规格前后一致。
- **周报可用**。核对公开版与附件的章节、主要图表及数字；在官网现行内容安全策略下检查筛选、图表、弹层关闭、键盘焦点返回和独立打开。仅在读者打开报告后加载完整版。
- **移动端可读**。在约 390、768、1440 像素宽度检查案例、导航、截图、报告和联系入口。密集表格提供可读的局部取景；核心说明即使关闭 JavaScript 也可阅读。
- **可交付**。在最终官网树运行 `npm run format:check`、`npm run lint`、`npm run typecheck`、`npm test`，检查构建产物、图片路径和脱敏结果。PR 中只包含官网代码、公开素材及必要测试。上线按官网现行发布流程另行执行。
